# B-005 API v1 contract and connector ingest

Adopt the repo-committed API contract as the system’s stable boundary, aligned with existing `docs/api/contract-v1.md` and the decision docs pattern under `docs/architecture/`. Expose UI/session needs via server-driven navigation (`GET /sessions/{id}/next-block`), list filters/pagination, and fact-rich artifact reads (`/artifacts/{name}` includes status, confidence, source). Keep connector ingest narrowly scoped to `POST /connector/ingest` with versioned metadata and per-site signed tokens; reject any payload containing message bodies to preserve the append-only, boundary-safe ingest model already reflected in `connector/src/connector/core_boundary.py` and the append-only integration test area. Tradeoff: stable client contract vs. server-side flexibility. Downstream implementers should keep auth/identity, `recorded_at`, and a11y tokens explicit but unresolved until follow-up decisions.
